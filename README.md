## 行きたいスポットの提出（メンバー用）

**→ https://sutadonman.github.io/okinawa-2026/wishlist.html**

ページ上のフォームに Google マップの共有URLを貼って送るだけ。Google アカウントもログインも要らない。送信するとスプレッドシートに行が追加され、下の集計とエリア地図がその場で更新される。

### 送信先のセットアップ（初回だけ・オーナーの作業）

提出先は Google スプレッドシート「沖縄2026 スポット希望リスト」（マイドライブの `/trip/202610沖縄/` 配下）。GitHub Pages は静的サイトなので、書き込みの受け口として Apps Script をウェブアプリにして挟む。

1. スプレッドシートを開き、**拡張機能 → Apps Script**
2. [apps-script.gs](apps-script.gs) の中身をまるごと貼り付けて保存
3. **デプロイ → 新しいデプロイ → 種類「ウェブアプリ」**
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**全員**（この設定でないとメンバーが送れない）
4. 初回は Google の承認画面が出る。「詳細」→「安全でないページに移動」で自分のスクリプトを承認する
5. 表示された `/exec` で終わるURLを `wishlist.html` の `API_URL` に入れる

`TOKEN` は `apps-script.gs` と `wishlist.html` で同じ文字列にしておく。いたずら投稿を弾くだけの合言葉なので、秘密の情報は入れない。変えるときは両方を揃えて直すこと。

デプロイ済みのスクリプトを直したときは、**デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」** で更新する。新規デプロイにするとURLが変わる。`wishlist.html` と `seisan.html` は同じウェブアプリURLを使っているので、片方のために貼り替えたぶんはもう片方にも効く。

### 権限が増えたときは承認を取り直す

短縮URLの展開には外部URLへのアクセス権（`script.external_request`）が要る。**再デプロイしただけでは承認画面が出ず、権限エラーで黙って失敗する**ので、以下をやる。

1. エディタ左下の**プロジェクトの設定（歯車）→「appsscript.json マニフェスト ファイルをエディタで表示する」**にチェック
2. 現れた `appsscript.json` を、このリポジトリの [appsscript.json](appsscript.json) の内容に置き換えて保存
3. 関数プルダウンで **`authorize`** を選んで**▶ 実行** → 承認画面で許可
4. **デプロイを管理 → 新バージョン**で反映

`authorize` は例外を握りつぶさないので、権限が足りなければ実行ログにそのまま出る。成功すると `code=302 location=https://www.google.com/maps/place/...` のようなログが残る。

うまくいかないときは `<ウェブアプリURL>?debug=<短縮URL>` を開くと、展開結果と失敗理由が JSON で返る。

### メンバーの使い方

提出者を **Otsu / Sugi / Runto** から選び、Google マップのリンク・種別（観光 / ご飯）・優先度（high / middle / low）を入れて送るだけ。スポット名とひとことは任意。選んだ提出者はブラウザに残るので、2件目以降は選び直さなくてよい。

リンクは Google マップの「共有」で出る短縮URLをそのまま貼ればよい。座標とスポット名はサーバー側で自動的に読み取る。

提出者を増やす・変えるときは、`wishlist.html` のラジオボタンと `apps-script.gs` の `MEMBERS` の両方を直す（スクリプト側でも3人以外の投稿を弾いている）。ダッシュボードの色分けは3人ぶんまで用意してある。

### 修正と取り下げ

提出者を選ぶと、フォームの下に**自分が出した分の一覧**が出る。ここで優先度を選び直すか、取り下げボタンで消せる。判定はシートの内容が正なので、スマホで出してPCで消す、といった使い方もできる。

行の持ち主はシートの `ID` 列（7列目）で管理している。この列はスクリプトが自動で振るので、手で編集しないこと。既存行のIDは初回アクセス時に自動で埋まる。

取り下げは**シートから行を削除する**。誤って消したときは、スプレッドシートの ファイル → 変更履歴 から戻せる。

### 採否と種別

一覧表の「種別」「状態」列から切り替える。どちらも**場所そのものの属性**で共同の判断なので、自分の提出でなくても変更できる（優先度だけは本人のみ）。

- **採否**（採用 / 未定 / 不採用）— 不採用にするとシートには残したまま、地図と集計から外れる
- **種別**（観光 / ご飯）— 地図では **丸＝観光 / 四角＝ご飯**。地図上部のチップで絞り込める

地図は色（提出者）と大きさ・濃さ（優先度）を既に使っているため、種別は**形**で表している。ナイフとフォークのようなアイコンは、優先度 low の直径6pxでは潰れて読めない。

種別の列（8列目）は、既存行には自動で `観光` が入る。

なお、ログインを求めていないため「他人の名前を選べば他人の提出も消せる」状態ではある。身内3人での運用として許容しているが、スクリプト側では最低限、**選んでいる提出者と行の提出者が一致しないと修正・削除できない**ようにしてある。

同じスプレッドシートを直接編集してもよい（フォームと同じ行が増えるだけ）。[wishlist-template.csv](wishlist-template.csv) は、シートを作り直すときの雛形として残してある。

### 短縮URLとスマホ共有の扱い

短縮URL（`maps.app.goo.gl`）はブラウザから転送先を辿れないので、Apps Script 側（`resolveShort_`）がサーバーで展開する。

**PCとスマホで、共有リンクの中身が違う**点に注意。

| 共有元 | URLに入っているもの |
|---|---|
| PCのブラウザ | `@緯度,経度` と `!3d緯度!4d経度` |
| **スマホアプリ** | **施設IDのみ（`!1s0x34e5…:0x5a84…`）。座標なし** |

スマホ共有は座標を持たないが、`/place/` の部分に地点名は入っている（郵便番号と住所が前に付く形）。そこで `cleanPlaceName_` で店名だけ取り出し、`?api=1&query=<店名>` の形に置き換える。**座標はページ側が Places API で引いて埋める**（写真取得と同じ検索1回で済むので、追加の課金は発生しない）。

[resolved.json](resolved.json) は自動解決が入る前の手動対応の名残。いまは使わなくても動く。

## 立替・精算（メンバー用）

**→ https://sutadonman.github.io/okinawa-2026/seisan.html**

誰かが先に払ったぶんをここに出しておくと、最後に「誰が誰にいくら渡すか」が出る。ログイン不要なのは希望リストと同じ。

保存先は**同じスプレッドシートの2枚目のシート「立替・精算」**。無ければスクリプトが自動で作り、見出しも自分で書く。1枚目（スポット希望リスト）とは読み書きの経路が分かれていて、立替まわりの処理は1枚目に一切触れない。送信先の Apps Script も同じもので、**新しいデプロイURLは要らない**。

### 出し方

1. **あなたは** — Otsu / Sugi / Runto から選ぶ。希望リストと同じ選択がそのまま使われる（この端末にだけ残る）
2. **なにに使ったか / 金額** — 金額は円の整数。カンマや「円」を付けても読める
3. **立替えた人** — 初期値は自分。人の代わりに出すこともできる
4. **この支出を割る人** — チェックボックス。初期値は3人全員。ひとりぶんの立替なら、その人だけを選ぶ
5. **割り方** — 均等割か、メンバーごとに金額を個別入力するか

個別入力のときは、内訳の合計が金額と一致していないと送れない（ページ側とスクリプト側の両方で見ている）。

### 端数の扱い

均等割で割り切れないぶんは、**立替えた人の負担に寄せる**。1000円を3人なら 334 / 333 / 333 で、334 が立替えた人。立替えた人が対象に入っていないときは、対象の先頭（`MEMBERS` の並び順）に寄せる。

金額はすべて円の整数で扱い、小数は作らない。

### 精算

「精算の内訳を出す」を押すと、**シートを読み直してから**、送金の回数がいちばん少なくなる組み合わせを計算して出す。押しても記録は残らないので、何度でも出し直せる。渡し終えたら、その立替を消すか、そのまま残しておけばよい。

各人の「払った合計」「負担すべき合計」「差引」は一覧に常に出ている。差引がプラスなら受け取る側、マイナスなら払う側。

### 直す・消す

自分が出した立替だけ、フォーム下の一覧から直したり消したりできる。持ち主の判定は 7列目の `投稿者` と 8列目の `ID`（自動採番）で行う。`ID` 列は手で編集しないこと。

シートを手で直しても壊れないようにしてある。個別内訳の合計が金額と合わなくなった行は均等割として扱い、対象メンバーが空の行は全員として扱う。金額が読めない行と、立替者がメンバー外の行は集計から外れる。

## 持ち物（メンバー用）

**→ https://sutadonman.github.io/okinawa-2026/mochimono.html**

京都プロジェクト（[kyoto-2026](https://github.com/sutadonman/kyoto-2026)）の `mochimono.html` の仕組みを流用したもの。**中身のロジックだけ借りて、配色は沖縄側（琉球藍＋紅型）に合わせてある**ので、京都版の和紙色は使っていない。

品目は `ITEMS` に直書きなので、足すときはそこを直す。`who` を書くとその人だけの持ち物になる。

チェックの状態は **localStorage に人ごとに保存**され、サーバーには送らない。同じ端末を3人で回し見しても混ざらない。人の選択キー（`okinawa2026.who`）は希望リスト・精算ページと共通なので、どれかで選べば他でも選ばれた状態になる。

10月の沖縄向けに、京都版には無かった**水着・タオル・ラッシュガード・かかとの留まるサンダル・濡れ物を入れる袋**を足してある（Day3のマングローブカヤックで確実に濡れるため）。

## Google マイマップに取り込む

全31スポットを1枚の地図にまとめて、3人で共有・編集できます。

1. [okinawa-spots.csv](okinawa-spots.csv) を開き、右上の **Download raw file**（下向き矢印のアイコン）で保存する
2. [Google マイマップ](https://www.google.com/maps/d/) を開いて **新しい地図を作成**
3. 左パネルの **インポート** から、保存した CSV をアップロード
4. 「目印の位置に使う列」で **緯度** と **経度** の2つにチェック
5. 「マーカーのタイトルとして使う列」で **名前** を選択
6. 地図名を「沖縄 2026.10」などに変更し、右上の **共有** からメンバーに「編集者」権限を付与
7. 各自のスマホで Google マップ →「保存済み」→「マイマップ」から開ける（オフラインでも表示される）

### 旧版（最北端ルート）

差し替え前の旅程は [`index-v1.html`](index-v1.html) に残してある。Day3 が「慶佐次カヤック → アスムイハイクス → 辺戸岬」で約155km走る構成。

入れ替えた理由は優先度。提出シートで **アスムイハイクスも辺戸岬も low** だったのに Day3 を丸ごと使っていて、一方で **middle の提出8件を1件も拾えていなかった**。本部半島（エメラルドビーチ・備瀬のフクギ並木）と宮里そば、おきみゅー、ジェフ泡瀬、トロピカルビーチに振り替えて、**未消化の middle をゼロにした**。Day3 の走行は約155km → 約120km に減っている。

カヤックが午後枠（集合14:30・体験15:00〜17:00）しか取れない見込みになったため、Day3 の午前を本部半島に充てている。

道の駅許田も落とした。北部観光施設の**割引チケットが買える**のが実質的な価値だったが、エメラルドビーチは無料なので通常は影響しない。雨で美ら海水族館に振り替える場合だけ割引が効かなくなる。ブセナから10分なので保険で寄る選択肢は残る。

## 宿（3泊とも予約済）

3泊合計 **36,692円／名**。金額は3名1室（古宇利島は3名で一棟）での1名あたり。

| 10/09 金 | [isola base kouri](https://isola-base.com/kouri/)（今帰仁村古宇利・一棟貸し） | 13,100円 | **食事なし** | 予約済 |
| 10/10 土 | [ココガーデンリゾートオキナワ](https://cocogarden.com/)（うるま市石川） | 13,392円 | 朝食付 | 予約済 |

当初案（恩納 → 古宇利島 → うるま市街）から2か所ずれたので、旅程の時刻も合わせて直してある。

- **初日が恩納ではなく宜野湾** — 北谷からの移動は35分→15分に縮むが、翌朝の琉球村までが車30分になる。Day2 の出発を8:20に設定した
- **3日目が安慶名・みどり町ではなく石川** — 歩いて行ける居酒屋がないので、10/10（土）の夕食はホテル内のレストランを予約する。Day4 は宿の朝食を済ませて8:30発
- **10/09 は3泊で唯一の食事なし** — ただし夕食は島内の店でとるので、スーパーで買うのは**翌朝の朝食ぶんだけ**。Day3 は9:15発で、朝に島の店は開いていない

**おきみゅーを初日に置いた理由** — 常設展が沖縄の自然・歴史・民俗を一通り押さえる内容なので、旅の最初に見ると、あとのグスク・紅型・やんばるが理解しやすい。おもろまちは首里→宜野湾のほぼ直線上にあり、中城城跡を経由するより**初日の運転が25分短い**。屋内なので到着日の疲れと雨にも強い。

**中城城跡を最終日に回した理由** — 中村家住宅とは1.5km・車5分なので、北中城で一度降りれば2か所まとめて回れる。朝の勝連城跡と合わせるとグスク2つ＋古民家という並びになる。

首里城はスキップ。読谷エリア（残波岬・座喜味城跡・やちむんの里）は Day4 でうるまを選んだため見送り、やちむんは壺屋やちむん通りで代替。

## 座標の出どころ

玉陵・中村家住宅・琉球村・古宇利島・東村ふれあいヒルギ公園は共有された地図リンクから取得した正確な値。ラグナガーデンホテル・isola base kouri・ココガーデンリゾートオキナワは Google マップの施設ピンの値。中城城跡・今帰仁城跡・勝連城跡・果報バンタ・海中道路・ブセナ海中公園・壺屋やちむん通りは OpenStreetMap で照合した値。トロピカルビーチ・エメラルドビーチ・宮里そば・おきみゅー・ジェフ泡瀬店は Google マップの施設ピンの値。その他は施設の代表点（誤差数十〜百m程度）。飲食店は休業日が変わるため、地図リンクは店名検索にしてある。

営業時間・料金・宿泊料金は変動するので、予約前に各公式サイトで確認すること。

## 検索避けについて

`index.html` に `noindex` を入れてあるため、検索エンジンには載らない。URL を知っている人だけが到達できる状態。

さらに強くしたい場合は、`sutadonman.github.io` リポジトリの `robots.txt` に以下を追記する。プロジェクトページのサブパスに置いた `robots.txt` はクローラーに読まれないので、ドメイン直下に置く必要がある。

```
User-agent: *
Disallow: /okinawa-2026/
```
